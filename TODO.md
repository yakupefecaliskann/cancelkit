**Faz 6 notları:** Landing sayfasını canlı test ederken uygulama genelini etkileyen gerçek bir font bug'ı bulundu ve düzeltildi: `app/globals.css`'teki `html { @apply font-sans; }` kuralı `--font-sans` CSS değişkenini kullanıyordu, ama `app/layout.tsx` bu değişkeni (next/font ile) yalnızca `<body>` class'ına koyuyordu. CSS custom property'ler yalnızca alt öğelere (descendant) miras kalır, üst öğeye (`<html>`, `<body>`'nin ebeveyni) değil — bu yüzden `<html>` kendi `--font-sans`'ını bulamıyor, tarayıcının varsayılan serif fontuna (Times New Roman) düşüyordu. Başlıklar (`font-heading` class'ı taşıyan `h1`/`h2`/`CardTitle`) tesadüfen doğru görünüyordu çünkü onlar `<body>`'nin altındaki öğelerdi ve değişkeni oradan miras alabiliyorlardı; ama tüm gövde metni (paragraflar, butonlar, liste öğeleri — dashboard dahil, `/demo` sayfasında da doğrulandı) sessizce serif render ediliyordu. Düzeltme: font değişken class'ları `<body>`'den `<html>`'e taşındı. Artık tüm uygulamada (landing + dashboard + widget demo sayfası) gövde metni doğru şekilde Inter ile render oluyor — tarayıcıda `getComputedStyle` ile doğrulandı.
